# /knowledge — RE팀 업무 기록 조회

팀 레포에는 두 표면이 있다. **질문 성격을 보고 어디를 볼지 먼저 정한다.**

| 표면 | 담긴 것 | 이런 질문에 |
|---|---|---|
| `activity/<사람>/` | 일지 원본 (세션별 Done·Next, 날짜별) | "누가 뭐 했나", "어디까지 진행됐나" |
| `cards/` | 증류된 문제-해결 카드 | "이 에러 어떻게 푸나", "누가 겪어봤나" |

인덱스가 둘이니 헷갈리지 말 것: 레포 루트 `INDEX.md`는 **카드** 목록, `activity/INDEX.md`는 **활동** 목록이다 (`cards/INDEX.md`는 없다).

## 0. 준비 (항상 먼저)

레포 경로를 config에서 읽고 **최신화한다.** 안 하면 어제 데이터로 답하게 된다.

```bash
REPO=$(python3 -c "import json,os;print(os.path.expanduser(json.load(open('<TOOL_DIR>/config.json')).get('knowledge_repo','')))")
git -C "$REPO" pull --ff-only 2>/dev/null || true
```
경로가 비어 있으면 "팀 레포 미설정 — `install-knowledge.sh --repo <path>` 필요"라고 안내하고 종료.
(`pull`은 "읽기 전용" 규칙의 유일한 예외다 — 레포 내용을 바꾸는 게 아니라 원격 상태를 가져오는 것. 실패해도 계속 진행하되, 그때는 `git -C "$REPO" log -1 --format=%ci`로 마지막 동기화 시각을 확인해 답에 신선도를 밝힌다.)

## 1. 활동 질의 — "누가 뭐 했나 / 어디까지 했나"

```bash
ls "$REPO/activity"                                   # 팀원 목록
ls "$REPO/activity" | grep -i <이름 일부>              # 이름을 정확히 모를 때 (Hank → Taehan_Hank_Kim)
grep '| <날짜> ' "$REPO/activity/INDEX.md"             # 그날 전원·전 프로젝트 한 줄씩 (여기부터)
cat "$REPO/activity/<사람>/<프로젝트>/<날짜>.md"        # 세션 상세 (Done·Next)
```

- **오늘/특정일 요약**: `activity/INDEX.md`를 날짜로 grep한다 — 그날의 (세션 × 프로젝트)가 한 줄씩. 한 사람만 볼 거면 `activity/<사람>/_daily/<날짜>.md`도 같은 내용이다.
- **기간 질의**("이번 주"): INDEX를 날짜 범위로 grep해 목록을 만들고, 필요한 것만 프로젝트 파일로 내려간다.
- **날짜에 파일이 없을 때**: 레포가 낡은 것과 그날 기록이 없는 것을 **구분해서** 답한다. `git -C "$REPO" log -1 --format=%ci`가 최근이면 "동기화는 됐고 그날 기록된 세션이 없다"이다. 단정 대신 이렇게 말할 것.

### 진척 질의 — "X를 어디까지 했나"

**프로젝트 디렉토리부터 열지 말 것.** 한 세션이 여러 프로젝트 디렉토리에 걸치는 일이 흔해서(작업 중 `cd`), 한 디렉토리만 보면 같은 업무의 절반을 놓친다. **주제로 먼저 훑는다:**

```bash
grep -ril <주제어> "$REPO/activity/<사람>"     # 여러 주제어를 각각 시도
```

**영어 약어로만 찾으면 0건이 나온다.** 일지 본문은 한국어다 — `sso`로 grep하면 정작 SSO 세션 파일이 하나도 안 잡히고(본문은 "게이트웨이 로그인", "자동 로그인"이라고 쓴다), 무관한 파일만 걸린다. **약어 + 한국어 증상어 + 관련 고유명사를 모두** 돌린다: `sso` → `로그인`·`인증`·`게이트웨이`·`FLASK_SECRET_KEY`.

1. 걸린 파일을 **날짜순**으로 읽어 `Done`(된 것) / `Next`(남은 것)을 모은다.
2. **마지막 날짜의 `Next`가 곧 남은 일** — 단, **마지막 세션이 다른 주제라면 그 주제가 마지막으로 언급된 날짜까지 거슬러 올라간다.** Next는 다음 세션으로 이월되지 않으므로, 최신 파일에 그 주제가 없다고 끝난 게 아니다.
3. **같은 주제의 카드를 반드시 확인한다 — 생략하면 오답이 나온다.** `## 검증 상태`가 완료 여부를 말해주는 유일한 필드인 경우가 많다("방향만 정리(적용 미검증)" = 코드는 됐고 런타임 검증이 남음).
   - **카드가 활동보다 최신일 수 있다.** 활동의 마지막 `Next`("아직 착수 안 함")와 카드의 `검증 상태`("구현 완료, 검증 대기")가 어긋나면 **카드를 믿는다** — 실측된 실제 사례다.
   - 카드 `sources`의 날짜에 해당하는 활동 파일이 없으면 **일지에 안 잡힌 작업이 있다는 신호**다. `excluded.md`도 함께 확인한다.

> 진척은 **서술형**이다. 티켓 연동이 없으므로 "몇 %"가 아니라 "어디까지 됐고 무엇이 남았다"로 답한다. 기록이 끊긴 구간은 "기록 없음"이라고 밝히고, 완료 여부를 추측으로 단정하지 말 것.

## 2. 기술 질의 — "이 문제 어떻게 푸나"

1. **카드 검색**: 질의를 키워드 2~4개로 쪼개 AND로 좁히고, 0건이면 OR로 완화.
   ```bash
   ls "$REPO/cards"/*.md | xargs grep -lie <kw1> | xargs grep -lie <kw2>
   ```
   - **카드 본문은 한국어다.** 영어 키워드(`cookie`, `login`, `timeout`)로 AND 검색하면 0건이 나오기 쉽다 — 반드시 한국어 대응어를 같이 넣는다 (login→로그인, cookie→쿠키, slow→느림/지연). 반대로 한국어 증상은 영어로도 변환한다 (막혀요→blocked/403). **양방향으로 시도할 것.**
   - 벤더·제품명(Upstage, LangGraph, FastAPI)으로도 시도. 0건이면 일반어로 넓힌다 — 본문은 일반어이고 벤더명이 tags에만 있을 수 있다.
   - 카드 하나를 찾았으면 **같은 증상의 다른 층위**가 있는지 레포 루트의 `INDEX.md`(카드 목록)를 훑는다. "로그인이 안 된다" 하나에 인증·프록시·복귀경로 카드가 따로 있을 수 있다.
2. **활동 폴백**: 카드가 0건이면 **`activity/` 전체를 grep**한다. 카드화되지 않은 작업이 훨씬 많다.
   ```bash
   grep -rile <kw> "$REPO/activity"
   ```
3. **제시**: 카드는 각색 없이 인용한다. `## 검증 상태`를 반드시 함께 전한다(검증됨 / 방향만 / 진단만). `sources`의 **작성자·프로젝트·날짜**를 알려 "이 사람에게 물어보라"까지 연결한다.
4. 둘 다 0건이면: "팀 기록에 없음 — 해결하면 다음 주 추출에서 자동으로 카드가 된다"고 안내.

## 3. 리포트 요청 — "이 기간 정리해줘"

**`activity/INDEX.md`에서 시작한다.** 기간 전체의 (날짜·사람·프로젝트·제목·세션)이 한 파일에 있다.

```bash
grep '| 2026-07-' "$REPO/activity/INDEX.md"        # 그 기간 전 세션을 한 번에
```

1. 제목을 훑어 리포트에 들어갈 세션을 **고른다.** 그 다음에야 해당 파일만 연다.
2. **프로젝트 이름으로 거르지 말 것.** 폴더명은 작업 당시 cwd의 레포명이지 고객명이 아니다 — 실측에서 SKT 작업의 절반 이상이 `zez-server`·`agent-runtime`·`doc-console`에 있어 `skt-*` 필터는 관련 자료의 절반을 놓쳤고, **누락이 결과에 드러나지 않는다.**
   - 고객 축에 가장 가까운 것은 **워크스페이스 열**이다(`grep '| skt-agent-proj |'` → 폴더 필터 18건 vs 29건).
   - 그래도 힌트일 뿐이다. **반대 방향 오류도 있다** — `skt-*` 폴더나 SKT 워크스페이스 안에 고객과 무관한 작업(도구 문의 등)이 섞인다. 최종 판단은 제목으로, 확실히 해야 하면 본문으로.
3. **세션 열은 Claude Code 세션 ID이지 작업 단위가 아니다.** resume으로 몇 주씩 이어져 한 ID가 수십 행에 걸친다(실측: 한 세션이 26일·20행). **같은 날 + 같은 주제**일 때만 한 건으로 묶고, 그 밖에는 제목으로 판단한다.
4. 관련 `cards/`를 근거로 붙인다 — 카드는 이미 증류돼 있어 인용하기 좋다.

### 외부(고객) 제출 문서라면 — 원문 인용 금지, 아래를 하나씩 확인

이 레포는 사내용이라 아무것도 가려져 있지 않다. 초안을 넘기기 전에 **전부** 훑는다:

- [ ] **사번·실명** (예: `1109421`, 담당자 이름) → 삭제
- [ ] **내부 IP·포트** (`100.64.x.x`, `172.18.x.x:13100`) → "신규 서버", "내부 게이트웨이"
- [ ] **내부 호스트명** (`*.sktelecom.com`, `ec2-*`) → 일반화
- [ ] **GitLab/Confluence 경로·MR 번호·pageId** → 삭제
- [ ] **커밋 해시·브랜치명** → 삭제 (필요하면 "수정 반영"으로)
- [ ] **환경변수명** (`FLASK_SECRET_KEY` 등) → "세션 서명 키" 같은 역할명
- [ ] **미해결/과거 취약점 이력** (인가 누락, IDOR, DROP 위험) → 포함 여부를 **사용자에게 먼저 확인**

`cards/`가 상대적으로 정제돼 있지만 면제는 아니다. 이 레포에서 나가는 모든 문서는 사람이 한 번 걸러야 한다.

## 규칙

- 카드·일지 내용을 **각색하지 않는다.** 해결 절차의 정확성이 생명이다.
- 이 스킬은 **읽기 전용**이다. 카드·활동을 쓰거나 고치지 않는다 (쓰기는 주간 추출과 동기화의 몫).
- 사내 레포이므로 고객명·서버 주소·담당자가 그대로 있다. 그대로 인용하되, **외부로 나가는 문서에 붙일 때는 사용자에게 확인**한다.
